====================================

Purpose: identify the original C++ workload's CPU hotspots for the CUDA design.
This is an instrumented, sampled CPU profile; it is NOT a GPU timing or a
measurement of GPU speedup. No CUDA device was involved in this run.

one worker thread, seed 2026, no per-generation CSV, no verification simulation.

Interpretation and limits
-------------------------
The synthesis/evaluation path is the largest sampled CPU component for this
specific problem, seed, population, and generation count. Sampling, repair, and
probability updates together account for approximately 41.5% of sampled CPU time.
Accelerating synthesis alone therefore leaves material CPU work; the profile
cannot justify a claimed end-to-end GPU multiplier. GPU transfer, scheduling,
kernel launch, concurrency, different workloads, and GPU hardware were not
measured here. Retaining CPU sampling and updates supports reproducible original
search behavior, with the expected corresponding cost.

-pg changes execution cost. gprof reports sampled program counters and function
call instrumentation; inlining and tail calls can affect function attribution
and call counts. Use the grouped percentages as approximate hotspot evidence,
not exact costs for an uninstrumented build. Sub-second components have limited
sampling precision. This was a single profile, not a statistical benchmark.
